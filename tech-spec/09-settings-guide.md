# Settings Guide — ccms-repair

> **Version:** 1.0.0 | **Last Updated:** 2026-04-20 | **Status:** Draft

---

## ภาพรวม (Overview)

ฟีเจอร์การตั้งค่าระบบ (Settings) ในโครงสร้างของระบบ CCMS ปัจจุบัน มีจุดมุ่งหมายหลักเพื่อไว้สำหรับควบคุมระยะเวลามารตรฐานความสำเร็จรายวัน หรือที่เรียกว่า **Service Level Agreement (SLA)** โดยหน้าที่ของมันคือเป็นมาตรวัด เพื่อแจ้งเตือนช่าง และผู้รับผิดชอบเมื่อใบเคลมมีแนวโน้มคืนลูกค้าช้ากว่ากำหนด

## การเข้าถึง (How to access)

การตั้งค่า SLA ของระบบ ถูกออกแบบมาให้อยู่ในจุดที่ผู้บริหารสามารถควบคุมได้ง่าย โดยสามารถเข้าถึงได้โดยตรงจากหน้า **แดชบอร์ดสรุปสถิติ (Analytics)** ผ่านปุ่มที่มีไอคอนฟันเฟือง `⚙️ ตั้งค่า SLA` ที่ด้านขวาบน

---

## ฟีเจอร์หลักของการตั้งค่า

### 1. การกำหนดระยะเวลา SLA สูงสุด (SLA Threshold Limit)

ปรับแต่งจำนวนวันที่รับได้ (เพดานจำกัด) ที่ระบบอนุญาตให้งานซ่อมค้างอยู่ในบริษัทได้ ก่อนที่ระบบหน้าแดชบอร์ดจะดึงนำรายชื่อขึ้นมาประกาศในหมวดหมู่ **"ค้างเกินกำหนด"** (Overdue/Breaches)

- **ค่าเริ่มต้น (Default)**: `14 วัน`
- **การประมวลผล**: ส่งผลกับตัวแปรเบื้องหลังทันทีแบบ Reactivity (ไม่ต้อง Refresh เว็บ)
- **การจัดเก็บข้อมูล**: บันทึกอัตโนมัติในเบราว์เซอร์เซสชันชั่วคราว (Web Storage API)

**วิธีปรับค่า SLA ทาร์เก็ต:**
1. กดเมนูเข้าสู่หน้า แดชบอร์ดสรุปผล
2. กดปุ่ม `⚙️ ตั้งค่า SLA` บริเวณมุมขวาบนของหน้าเว็บ
3. หน้าต่าง Pop-up (จาก SweetAlert2) จะโผล่ขึ้นมา เพื่อให้ป้อนเงื่อนไขเวลา
4. กรอกตัวเลขจำนวน "วัน" ที่เป็นนโยบายปัจจุบันของบริษัท เช่น เปลี่ยนจาก 14 เป็น `7` 
5. กดยืนยันการเปลี่ยนแปลง (บันทึก) ระบบจะคำนวณกราฟสรุปใหม่ทันที

### 2. ผลกระทบหลังบันทึก (System Effects)

- กราฟแจ้งเตือนรายชื่อลูกน้องที่ดองงานค้าง จะลดลงหรือเพิ่มขึ้นตามความตึงเครียดของนโยบายตัวเลขที่รับค่ามาใหม่
- ไฟล์ Export ออกเป็น Excel หัวข้อที่ 4 (สรุปปัญหา SLA Break) จะสกัดข้อมูลตามตัวเลขนี้เป๊ะๆ เมื่อกดโหลด ให้ออกเอาไปทำ Report ส่งเจ้านายต่อได้โดยตรง

## การแก้ปัญหาเบื้องต้น (Troubleshooting)

### เปิดเครื่องใหม่แล้วค่าจำจำกัดตั้งกลับไปเป็นค่าเดิม
- **สาเหตุ:** การตั้งค่าในปัจจุบันเซฟตัวแปรรองรับไว้ที่ `localStorage` ของเบราว์เซอร์ภายในคอมพิวเตอร์ หรือ Chrome Profiles ของเครื่องนั้นๆ 
- **วิธีแก้:** ถ้าสลับเปลี่ยนเปิดใช้คอมพิวเตอร์เครื่องอื่น ต้องกดปุ่มเข้าไปตั้งค่าเป้าหมายวัน (SLA Days) ให้บริษัทใหม่อีก 1 รอบ

## Technical Context (สำหรับนักพัฒนาโปรแกรมเมอร์)

ระบบใช้วิธีดึง Hook State `slaDays` ภายใน `DashboardAnalytics.jsx` เชื่อมเข้ากับ Storage
คีย์ `localStorage` ที่นักพัฒนาสามารถเข้าถึงเพื่อเรียกใช้งานในอนาคตได้:
- Key: `cmms_sla_days`
- Value type: `String (สามารถ ParseInt เพื่อไปใช้ในสมการ Date)`

**ตัวอย่างการนำไปพัฒนาต่อ:**
```javascript
// โหลดค่า SLA ทันทีตอน Mount Component
const savedSLA = localStorage.getItem('cmms_sla_days');
if (savedSLA) setSlaDays(parseInt(savedSLA));

// เสียบทับเขียนอัปเดตใหม่
localStorage.setItem('cmms_sla_days', newSla);
```
