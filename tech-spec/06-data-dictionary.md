## Dashboard Metrics Fields

| Field | Type | Description |
|-------|------|-------------|
| `totalPending` | number | จำนวนงานที่ยังค้างอยู่ในระบบ (สถานะงานใดๆ ที่ยังไม่ส่งคืนลูกค้า) |
| `totalCompleted` | number | จำนวนงานที่สำเร็จและส่งมอบเครื่องคืนลูกค้าไปแล้ว (Closed cases) |
| `atCompany` | number | จำนวนงานที่สถานะเครื่องปัจจุบัน "อยู่ที่บริษัท" (เช่น รับงานใหม่, พัสดุตีกลับ หรือ เพิ่งรับกลับจากศูนย์) |
| `atCenter` | number | จำนวนงานที่โครงสร้างแจ้งว่า "กำลังอยู่ที่ศูนย์เคลม" (ส่งเคลมไปแล้วยังไม่ตีกลับมา) |
| `avgE2e` | number | เวลาเฉลี่ยสิ้นสุดกระบวนการ (End-to-End Time) มีหน่วยการแสดงผลเป็น **วัน (Days)** |
| `avgStep1`, `2`, `3` | number | สถิติเวลาเฉลี่ยรายขั้นตอน 1, 2 และ 3 |
| `breaches` | array | รายละเอียดของผู้ใช้งานและหมายเลขเครื่องที่มีการซ่อมดองเกินเวลา SLA |

## Job & Claim Flow Mapping (สถานะงานซ่อม)

ระบบจัดการเอกสารและการรันสถานะงานซ่อม จะวิ่งเป็นวงจร One-way Flow ไปข้างหน้า โดยอนุญาตให้สามารถ Revert Flow ย้อนหลังได้บางจุดเพื่อความยืดหยุ่นหน้างานจริง

| ลำดับชิ้นงาน | Status Code (ในตาราง Database) | Action Checkpoint | ชื่อ Status ที่ User เห็น (หน้า UI Dashboard) | สีประจำสถานะ (Badge Color) |
|-------------|-----------------------|--------------------|---------------------------------|----------------------|
| 1 | `Pending` | ตอนกรอกฟอร์มเพิ่มงานรับซ่อมใหม่ | **รออนุมัติ / รอรับเรื่อง** | ตะกร้าคำสั่ง (Red Notification) |
| 2 | `New` | ตอนแอดมินหรือช่างกดเช็คของเข้าคลัง | **รับเครื่องมารอซ่อม** | สีฟ้าอ่อน (Blue-100) |
| 3 | `Claimed` | ตอนพนักงานกดสร้างเอกสารส่งเคลมศูนย์ | **ส่งเคลมศูนย์** | สีม่วงอ่อน (Purple-100) |
| 4 | `Claimed` *(คู่กับ date_received_back)* | พนักงานกดเซ็นรับของกลับจากศูนย์ | **รับกลับอยู่ที่บริษัทแล้ว** | สีส้มอ่อน (Orange-100) |
| 5 | `Returned` | พนักงานกรอกรายละเอียดพัสดุจัดส่งคืนลูกค้า | **ส่งคืนลูกค้าแล้ว** | สีเขียว (Green-100) |

*(สถานะข้อยกเว้น)*
| ข้อยกเว้น | `ClaimFailed` / `is_return_failed` | เมื่อพัสดุตีกลับ/ยกเลิกเคลม/ขนส่งมีปัญหา | **พัสดุตีกลับ (รอส่งซ้ำ)** หรือ **ส่งเคลมไม่สำเร็จ** | สีแดง (Red-100) |

## สรุป Flow การทำงาน

```text
[เพิ่มงานซ่อมเข้าระบบ]
      ↓ (Pending) — เครื่องรอตรวจสอบอนุมัติ
[กดอนุมัติรับของ]
      ↓ (New) — รับเครื่องเข้าสต็อก รอคิวส่งศูนย์
[กดส่งศูนย์บริการ]
      ↓ (Claimed) — ระบบสร้างตาราง 'claims' พร้อมเลขพัสดุ Track Number
[กดรับของกลับบริษัท]
      ↓ (Received Back) — อัปเดตเวลา 'date_received_back' สำหรับปิดเป้า Step 2
[กดจัดส่งคืนลูกค้า]
      ↓ (Returned) — ปิดเคสสำเร็จงานซ่อม อัปเดต 'date_returned_customer' 
```

*(หมายเหตุ: แอดมินสามารถกดปุ่ม "ย้อนสถานะตีกลับ" เพื่อรีเซ็ตโครงสร้างกรณีสินค้าส่งไม่สำเร็จ ให้ย้อนกลับมารอจัดส่งใหม่ที่สถานะ Received Back อีกรอบได้โดยไม่เสียประวัติกาลเวลาทิ้ง)*

## SLA Duration Formula (คำนวณวงจรเวลารายวัน)

ระบบเก็บเวลาด้วยสูตรหาผลต่างดังนี้:

| Stage | วิธีตั้งค่าสมการจำกัดเวลา (Days) | การคำนวณความล่าช้า (Bottleneck) |
|-------|--------------------------|----------|
| **Step 1:** | `date_sent` - `date_received` | เวลาที่ดองของไว้ที่บริษัทสาขาต้นทาง ก่อนจะถูกนำไปส่งต่อ |
| **Step 2:** | `date_received_back` - `date_sent` | รอบระยะเวลารอที่สูญเสียไปทั้งหมด ของศูนย์รับแก้ปัญหาใหญ่ |
| **Step 3:** | `date_returned_customer` - `date_received_back` | รอบระยะเวลาแพ็คของเตรียมจัดส่งหลังได้ของคืนกลับมาบริษัท |
| **Total:** | `date_returned_customer` - `date_received` | ความล่าช้าแบบรวมเบ็ดเสร็จตั้งแต่ลูกค้ายกของมา จนถึงของกลับไปถึงลูกค้า |
